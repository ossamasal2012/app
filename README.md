# متجر تطبيقات OSSAMA SALAM HADI — الإصدار الجديد

موقع ويب ثابت (بدون أي مكتبة خارجية) لتوزيع ملفات APK، مع **عدّاد تحميلات ذكي** لا يحتسب النقرات ولا محاولات البدء، بل **جهازاً واحداً لكل تطبيق فقط بعد وصول الملف كاملاً**.

> الموقع يعمل فور رفعه حتى بدون العدّاد (تظهر البطاقات وأزرار التحميل المباشر). لتفعيل الأرقام تحتاج الخطوة 2 (مجانية).

---

## 1) محتويات المجلد

```
index.html            الصفحة الرئيسية
apps.json             ← الملف الوحيد الذي تعدّله لإضافة التطبيقات
assets/               التنسيق + السكربت + الخطوط (محلية بالكامل)
backend/              خادم العدّاد (Cloudflare Worker + قاعدة D1)
  worker.js  schema.sql  wrangler.toml
tools/refresh-apps.mjs   يحسب حجم وتاريخ وبصمة SHA-256 لكل APK تلقائياً
.github/workflows/       يشغّل السكربت السابق كل 6 ساعات على GitHub
_headers              ترويسات أمان كاملة (Cloudflare Pages / Netlify)
```

## 2) نشر الموقع

ارفع **كل** محتويات المجلد إلى مستودع GitHub بنفس الهيكل ثم فعّل **Settings ← Pages ← Deploy from a branch**. (الملف `.nojekyll` موجود كي لا تعبث Jekyll بالملفات.)

للتجربة على حاسوبك: `python3 -m http.server 8000` داخل المجلد ثم افتح `http://localhost:8000`.

## 3) تفعيل عدّاد التحميلات (مرة واحدة، بدون بطاقة بنكية)

العدّاد المشترك بين الزوار يحتاج خادماً صغيراً؛ الموقع الثابت وحده لا يستطيع. نستخدم Cloudflare Workers + D1 (الخطة المجانية تكفي عادةً لآلاف التحميلات يومياً؛ راجع الحدود الحالية في صفحة أسعار Cloudflare).

**من لوحة Cloudflare (بدون أوامر):**

1. أنشئ حساباً مجانياً على `dash.cloudflare.com`.
2. **Storage & databases ← D1 SQL database ← Create database**، سمِّها `ossama-store`. افتح تبويب **Console** والصق كامل محتوى `backend/schema.sql` ثم **Execute**. (إن رفضت اللوحة تنفيذ الملف دفعة واحدة، نفّذ الأوامر واحداً واحداً.)
3. **Workers & Pages ← Create ← Create Worker**، سمِّه `ossama-store-api` واضغط **Deploy**، ثم **Edit code**، احذف الكود الموجود والصق محتوى `backend/worker.js` ثم **Deploy**.
4. من صفحة الـ Worker: **Settings ← Bindings ← Add ← D1 database**. اسم المتغيّر `DB` (بالضبط) واختر قاعدة `ossama-store`.
5. **Settings ← Variables and Secrets** وأضف:
   - `SITE_URL` (نص): رابط موقعك كاملاً وينتهي بـ `/` مثل `https://name.github.io/repo/`
   - `SECRET` (سرّي **Secret**): نص عشوائي طويل (32 حرفاً فأكثر). لا تشاركه ولا تضعه في الموقع.
   - `ADMIN_KEY` (سرّي، اختياري): لعرض تقرير الإدارة.
6. افتح `https://ossama-store-api.<حسابك>.workers.dev/api/health` فيجب أن ترى `"ok":true`. إن ظهر `db:false` أو `secret:false` أو `site:false` فالمتغيّر المقابل ناقص.
7. الصق رابط الـ Worker (بدون `/` في آخره) في `apps.json` داخل الحقل `"api"`.

**أو بسطر الأوامر** (من داخل `backend/`): `wrangler login` ← `wrangler d1 create ossama-store` (انسخ `database_id` إلى `wrangler.toml`) ← `wrangler d1 execute ossama-store --remote --file=schema.sql` ← `wrangler secret put SECRET` ← `wrangler deploy`.

> إن كان لـ Worker نطاق مخصّص غير `workers.dev` فأضِفه إلى `connect-src` داخل وسم CSP في `index.html` (وفي `_headers`).

## 4) إضافة تطبيق

أضف كائناً جديداً داخل `apps` في `apps.json`. **`id` يجب أن يكون فريداً** (أحرف إنجليزية صغيرة وأرقام وشرطة)، وإلا اختلطت عدّادات التطبيقات.

| الحقل | مطلوب | ملاحظات |
|---|---|---|
| `id` | نعم | مثل `my-app`. لا تغيّره لاحقاً وإلا بدأ عدّاد جديد |
| `name` | نعم | اسم التطبيق |
| `downloadUrl` | نعم | رابط https مباشر (GitHub Releases) |
| `icon` | لا | رابط أو مسار محلي مثل `assets/icons/app.png` (المحلي أكثر خصوصية) |
| `tagline` / `description` | لا | سطر تعريفي / وصف |
| `version` / `minAndroid` | لا | مثل `2.2` و `5.0` |
| `sizeBytes` / `updated` / `sha256` / `checked` | لا | **يملؤها السكربت تلقائياً** (انظر الفقرة 7) |
| `certSha256` | لا | بصمة شهادة توقيع التطبيق لمن يريد التحقق الأعمق |
| `changelog` | لا | قائمة نصوص قصيرة لـ «ما الجديد» |
| `apkName` | لا | اسم الملف عند التحميل، مثل `my-app.apk` |

## 5) كيف يعمل العدّاد (طبقات متعاونة)

| # | الطبقة | ما تمنعه |
|---|---|---|
| 1 | **حارس النقرات** في المتصفح: نقرة واحدة فعّالة، وباقي النقرات تُهمل 7 ثوانٍ | 100 ضغطة = طلب واحد |
| 2 | **تذكرة تحميل موقّعة** (HMAC) وقصيرة العمر، لا يُحتسب شيء بدونها | التلاعب المباشر بالـ API |
| 3 | **معرّف جهاز عشوائي موقّع** يُحفظ في localStorage + Cookie + IndexedDB ويُرمَّم من أيٍّ منها | العودة لاحقاً بنفس المتصفح |
| 4 | **قيد فريد في القاعدة** (تطبيق + جهاز) مع عدّاد يُحدَّث ذرّياً | التكرار مدى الحياة مهما مرّ من وقت |
| 5 | **الاحتساب بعد اكتمال الملف**: الملف يمرّ عبر الـ Worker ولا يُسجَّل إلا إذا أُرسل كاملاً ولم ينقطع الاتصال | بدء التحميل ثم الإلغاء |
| 6 | **استعادة الجهاز بعد مسح البيانات**: بصمة تقنية (مُشفّرة داخل المتصفح) + الشبكة نفسها خلال 90 يوماً | مسح بيانات المتصفح ثم إعادة التحميل |
| 7 | **حدود معدّل** لكل جهاز وكل شبكة، وتحقق من Origin، وحماية SSRF | الإغراق والسكربتات |

**حدود صادقة:** لا يوجد نظام ويب يعرف الجهاز بدقة 100%. الحالات التي قد تُحتسب فيها التحميلة كجهاز جديد: مسح بيانات المتصفح **مع** تغيّر الشبكة، أو التحميل من متصفح آخر على نفس الهاتف، أو الوضع الخاص. وعمداً **لا ندمج** أجهزة مختلفة بالتخمين (فعدّاد أقل من الحقيقة أسوأ من زيادة طفيفة)، لذلك تُستعاد البصمة فقط حين يتوفر طراز الجهاز (Chrome على أندرويد) وتتطابق الشبكة. كذلك يُحتسب الاكتمال عند انتهاء **إرسال** الملف من الخادم دون انقطاع، وقد يكون جزء صغير من الطرف الأخير في ذاكرة الشبكة المؤقتة لحظة الإلغاء المتأخر جداً.

إن قُطع الاتصال بخدمة العدّاد لأي سبب، يبدأ التحميل مباشرة من GitHub دون احتسابه ولا يُمنع المستخدم أبداً.

## 6) الأمان والخصوصية

- **سياسة CSP صارمة**: لا سكربتات مضمّنة ولا مكتبات خارجية (استُبدل Tailwind وLucide وGoogle Fonts بكود وخطوط محلية)، فلا اتصال بأي طرف ثالث سوى خادم العدّاد.
- كل النصوص تُدرج بـ `textContent` (لا `innerHTML`) فلا ثغرة XSS، مع تحقق من `apps.json` ومن روابط التحميل (https فقط).
- خادم العدّاد يجلب الملفات **من مضيفين تحدّدهم أنت فقط** (`UPSTREAM_HOSTS`، افتراضياً `github.com`) ويرفض أي POST من غير موقعك.
- **لا يُخزَّن عنوان IP** ولا أي قيمة خام: تُخزَّن هاشات HMAC فقط، وتُحذف روابط البصمة بعد 90 يوماً، ويُحذف أي جهاز لم يكمل تحميلاً بعد 30 يوماً.
- نافذة **«الخصوصية»** للمستخدم: ثلاثة مستويات (قياسي / خصوصية أعلى / بدون تعريف كلياً)، وزر **«حذف بياناتي»** يمسح كل شيء وينقص العدّاد تبعاً لذلك. وتُحترم إشارة GPC تلقائياً.
- **ما أُزيل عمداً**: عبارتا «آمن 100%» و«فحص الحماية» لأنهما ادّعاءان لا يمكن إثباتهما، وحلّ محلّهما شيء يمكن التحقق منه: بصمة SHA-256 لكل ملف. كما صُحّح خطأ كان في كودك القديم: التطبيقان يحملان `id: 1` معاً، ما كان سيدمج عدّاديهما.

## 7) بصمات الملفات تلقائياً (SHA-256)

على GitHub: تبويب **Actions ← «تحديث بصمات التطبيقات» ← Run workflow**. يحمّل السكربت كل APK ويكتب في `apps.json` الحجم والتاريخ والبصمة، ثم يحفظها في المستودع (ويعيدها تلقائياً كل 6 ساعات دون تعديل إن لم يتغيّر شيء). أو محلياً: `node tools/refresh-apps.mjs apps.json`.

> بعد نشر إصدار جديد ينقضي وقت قصير قد تختلف فيه البصمة المعروضة عن الملف الجديد حتى يعمل السكربت. شغّله يدوياً بعد كل إصدار.

## 8) تقرير الإدارة

إن أضفت `ADMIN_KEY`:

```
curl -H "Authorization: Bearer <ADMIN_KEY>" https://<worker>/api/admin/report
```
يعرض التحميلات لكل تطبيق، وعدد الأجهزة، وتحميلات آخر 30 يوماً يومياً. وإن شككت في انحراف الأرقام لأي سبب: `curl -X POST -H "Authorization: Bearer <ADMIN_KEY>" https://<worker>/api/admin/reconcile` يعيد بناءها من سجل التحميلات.

## 9) خيارات متقدمة (متغيرات الـ Worker)

- `DOWNLOAD_MODE=redirect`: بدل تمرير الملف عبر الـ Worker، يُحوَّل الزائر مباشرة إلى GitHub ويُحتسب عند **بدء** التحميل بعد التحقق من التذكرة (أخف على Cloudflare لكنه أقل دقة). الافتراضي `proxy`.
- `ALLOWED_ORIGINS`: نطاقات إضافية مسموحة (نطاق مخصّص أو `http://localhost:8000` للتجربة).
- `UPSTREAM_HOSTS`: مضيفو ملفات APK المسموحون، مفصولون بفواصل.

## 10) اختبارات أُجريت على هذه النسخة

- خادم العدّاد داخل بيئة workerd الحقيقية مع D1: 44 فحصاً (تكرار، إلغاء منتصف التحميل، استعادة الجهاز، تلاعب بالتذاكر والتوقيع، حدود المعدّل، الحذف، الإدارة).
- المتصفح الحقيقي (Chromium يحاكي هواتف أندرويد) مع الخادم: 30 فحصاً من الواجهة إلى الخادم (نقرات متكررة، اكتمال، مسح البيانات، جهاز آخر، وضع بدون تعريف، تعطّل الخادم).
- لم يُجرَّب على Cloudflare الفعلي ولا على هواتف حقيقية؛ اختبر بعد النشر: حمّل من هاتفك وراقب `/api/stats`.

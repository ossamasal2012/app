# متجر تطبيقات OSSAMA SALAM HADI — الدليل

موقع ويب ثابت (بدون أي مكتبة خارجية) لتوزيع ملفات APK مع **عدّاد تحميلات ذكي**: لا يحتسب النقرات ولا محاولات البدء، بل **جهازاً واحداً لكل تطبيق فقط بعد وصول الملف كاملاً**. كل تحميل يمرّ عبر خادم العدّاد الذي **يُخفي رابط المصدر** عن الزوّار.

---

## 1) محتويات المشروع

```
index.html               الصفحة الرئيسية
apps.json                ← الملف الوحيد الذي تعدّله لإضافة التطبيقات
assets/                  التنسيق + السكربت + الخطوط + أيقونات التطبيقات (icons/) — كلها محلية
backend/                 خادم العدّاد (Cloudflare Worker + قاعدة D1): worker.js  schema.sql  wrangler.toml
tools/refresh-apps.mjs   يحسب حجم وتاريخ وبصمة SHA-256 لكل APK تلقائياً
.github/workflows/       يشغّل السكربت السابق كل 6 ساعات على GitHub
_headers                 ترويسات أمان كاملة (Cloudflare Pages / Netlify)
```

## 2) نشر الموقع

ارفع محتويات المشروع إلى مستودع وفعّل الاستضافة (GitHub Pages أو Cloudflare Pages). مجلد `backend/` لا يحتاجه الموقع نفسه (تلصق ملفاته في Cloudflare فقط)، والأفضل ألا ترفعه إلى المستودع العلني.
للتجربة على حاسوبك: `python3 -m http.server 8000` داخل المجلد.

## 3) تفعيل خادم العدّاد (مرة واحدة، مجاني وبدون بطاقة بنكية)

من لوحة Cloudflare (`dash.cloudflare.com`):

1. **Storage & databases ← D1 SQL database ← Create database** باسم `ossama-store`. افتح تبويب **Console** والصق كامل محتوى `backend/schema.sql` ثم نفّذه. (الملف بلا تعليقات عمداً لأن الـ Console تدمج الأسطر في سطر واحد. تأكد بكتابة `/tables`: يجب أن ترى 5 جداول.)
2. **Workers & Pages ← Create ← Create Worker** باسم `ossama-store-api` ← **Deploy** ← **Edit code**: احذف الكود الموجود والصق `backend/worker.js` ← **Deploy**.
3. **Settings ← Bindings ← Add ← D1 database**: اسم المتغيّر `DB` (بالضبط) وقاعدة `ossama-store`.
4. **Settings ← Variables and Secrets** وأضف:

| المتغيّر | النوع | القيمة |
|---|---|---|
| `SITE_URL` | نص (Text) | رابط موقعك كاملاً وينتهي بـ `/` |
| `SECRET` | **Secret** | نص عشوائي طويل (32 حرفاً فأكثر). لا تشاركه |
| `SOURCES` | **Secret** | روابط ملفات APK الحقيقية بصيغة JSON (انظر تحت) |
| `ADMIN_KEY` | Secret (اختياري) | لعرض تقرير الإدارة |

قيمة `SOURCES` (سطر واحد، الأسماء هي `id` كل تطبيق في `apps.json`):

```
{"yalla-goal":"https://github.com/USER/REPO/releases/download/TAG/app-release.apk","second-challenge":"https://github.com/USER/REPO/releases/latest/download/app-release.apk"}
```

5. افتح `https://ossama-store-api.<حسابك>.workers.dev/api/health` فيجب أن ترى `"ok":true` و`"apps":` بعدد تطبيقاتك. إن كان `apps: 0` فالمتغيّر `SOURCES` ناقص أو فيه خطأ، وإن ظهر `db:false` أو `secret:false` أو `site:false` فالمتغيّر المقابل ناقص.
6. ضع رابط الـ Worker (بدون `/` في آخره) في `apps.json` داخل `"api"`.

**إن كنت نشرت النسخة السابقة:** الصق `worker.js` الجديد أولاً وأضف `SOURCES`، ثم ارفع ملفات الموقع الجديدة.
**أو بسطر الأوامر** (داخل `backend/`): `wrangler d1 create ossama-store` ← `wrangler d1 execute ossama-store --remote --file=schema.sql` ← `wrangler secret put SECRET` ← `wrangler secret put SOURCES` ← `wrangler deploy`.

> إن كان لـ Worker نطاق مخصّص غير `workers.dev` فأضِفه إلى `connect-src` في وسم CSP داخل `index.html` وفي `_headers`.

## 4) إخفاء هويتك (حماية مشاريعك)

- حُذف رابط GitHub من الموقع كلياً، ولا يظهر اسم حسابك في أي ملف من ملفات الموقع العلنية.
- روابط الملفات الحقيقية **لا توضع في `apps.json`** بل في `SOURCES` السرّي داخل Cloudflare، والزائر لا يرى إلا رابط الـ Worker. وأيقونة التطبيق مستضافة محلياً في `assets/icons/` (ملف WebP خفيف) بدل رابط `raw.githubusercontent.com` الذي كان يكشف اسم حسابك ومستودعك.
- **ما زال يكشفك:** (1) عنوان الموقع إن كان `اسمك.github.io` (الحل: Cloudflare Pages أو نطاق خاص)، (2) عنوان خادم العدّاد `اسمك.workers.dev` إن كان اسم حسابك في Cloudflare هو اسمك في GitHub: غيّره من **Workers & Pages ← Account details ← Subdomain ← Change** ثم حدّث الحقل `api` في `apps.json`، (3) المستودع نفسه إن كان عاماً، (4) الوضع `DOWNLOAD_MODE=redirect` لأنه يحوّل الزائر إلى رابط المصدر، (5) بيانات ملف الـ APK نفسه (اسم الحزمة والتوقيع).
- **حماية الكود فعلياً:** إخفاء الحساب لا يمنع من يجد المستودع العام من نسخه. الحل الجذري أن تجعل مستودعات التطبيقات **خاصة** وتنقل ملفات APK إلى مكان آخر مثل Cloudflare R2، ثم تضع رابطه في `SOURCES`.

## 5) إضافة تطبيق

أضف كائناً داخل `apps` في `apps.json` و**أضف رابطه في `SOURCES`** بنفس الـ `id`. الـ `id` يجب أن يكون فريداً (أحرف إنجليزية وأرقام وشرطة) وإلا اختلطت العدّادات. يُوحَّد تلقائياً إلى الأحرف الصغيرة (`Weather` ← `weather`) في الموقع والخادم ومفاتيح `SOURCES`، لكن اكتبه صغيراً من البداية. ولا تغيّره لاحقاً وإلا بدأ عدّاد جديد.

| الحقل | مطلوب | ملاحظات |
|---|---|---|
| `id` / `name` | نعم | المعرّف واسم التطبيق |
| `icon` | لا | مسار محلي مثل `assets/icons/app.webp` (الأفضل، حجم 256px) أو رابط https |
| `tagline` / `description` | لا | سطر تعريفي / وصف (يظهران في نافذة التفاصيل) |
| `version` / `minAndroid` | لا | مثل `2.2` و `5.0` |
| `sizeBytes` / `updated` / `sha256` / `checked` | لا | **يملؤها السكربت** (الفقرة 8) |
| `certSha256` | لا | بصمة شهادة توقيع التطبيق |
| `changelog` | لا | قائمة نصوص قصيرة لـ «ما الجديد» |
| `apkName` | لا | اسم الملف عند التحميل |
| `downloadUrl` | لا (لا يُنصح) | رابط علني احتياطي؛ وجوده يكشف المصدر لكنه يتيح التحميل إن تعطّل الخادم |

## 6) كيف يعمل العدّاد (طبقات متعاونة)

| # | الطبقة | ما تمنعه |
|---|---|---|
| 1 | **حارس النقرات**: نقرة واحدة فعّالة وباقي النقرات تُهمل 7 ثوانٍ | 100 ضغطة = طلب واحد |
| 2 | **تذكرة تحميل موقّعة** (HMAC) وقصيرة العمر | التلاعب المباشر بالـ API |
| 3 | **معرّف جهاز عشوائي موقّع** في localStorage + Cookie + IndexedDB يُرمَّم من أيٍّ منها | العودة بنفس المتصفح |
| 4 | **قيد فريد في القاعدة** (تطبيق + جهاز) مع عدّاد يُحدَّث ذرّياً | التكرار مدى الحياة |
| 5 | **الاحتساب بعد اكتمال الملف**: الملف يمرّ عبر الـ Worker ولا يُسجَّل إلا إن أُرسل كاملاً ولم ينقطع الاتصال | بدء التحميل ثم الإلغاء |
| 6 | **استعادة الجهاز بعد مسح البيانات**: بصمة تقنية (مُشفّرة داخل المتصفح) + الشبكة نفسها خلال 90 يوماً (`LINK_TTL` في `worker.js`) | مسح بيانات المتصفح |
| 7 | **حدود معدّل** لكل جهاز وشبكة، وتحقق من Origin، وحماية SSRF | الإغراق والسكربتات |
| 8 | **لا حذف**: لا يوجد زر ولا نقطة خادم لحذف سجلات التحميل، فالإحصاءات دائمة | إنقاص الأرقام |

**حدود صادقة:** لا يوجد نظام ويب يعرف الجهاز بدقة 100%. قد يُحتسب الجهاز مرتين عند مسح بيانات المتصفح **مع** تغيّر الشبكة، أو التحميل من متصفح آخر على نفس الهاتف. وعمداً **لا ندمج** أجهزة مختلفة بالتخمين (عدّاد أقل من الحقيقة أسوأ من زيادة طفيفة)، لذلك تُستعاد البصمة فقط حين يتوفر طراز الجهاز (Chrome على أندرويد) وتتطابق الشبكة. ويُحتسب الاكتمال عند انتهاء **إرسال** الملف من الخادم دون انقطاع.

إن تعطّل خادم العدّاد لا يبدأ أي تحميل (لأن كل تحميل يمرّ عبره) وتظهر رسالة واضحة للزائر.

## 7) الأمان والخصوصية

- **CSP صارمة**: لا سكربتات مضمّنة ولا مكتبات أو خطوط خارجية، فلا اتصال بأي طرف ثالث سوى خادم العدّاد. كل النصوص تُدرج بـ `textContent` فلا ثغرة XSS.
- الخادم يجلب الملفات **من مضيفين تحدّدهم أنت فقط** (`UPSTREAM_HOSTS`) ويرفض أي POST من غير موقعك، وتُوقَّع التذاكر والتوكن بـ HMAC.
- **لا يُخزَّن عنوان IP** ولا قيمة خام: هاشات HMAC فقط. وتُحذف روابط البصمة بعد 90 يوماً، ويُحذف أي جهاز لم يكمل تحميلاً بعد 30 يوماً.
- نافذة **«الخصوصية»** تعرض وضعاً قياسياً واحداً وتصرّح بوضوح أن العدّاد دائم ولا يمكن حذف سجلّ التحميل. حافظ على هذه الصياغة الصريحة، ولاحظ أن إلغاء حق المستخدم في الحذف قد يخالف قوانين حماية البيانات إن كان زوّارك في دول تفرضها (كالاتحاد الأوروبي).
- إشارة GPC لم تعد تُحترم لأن خيار «بدون تعريف» أُزيل.
- عبارتا «آمن 100%» و«فحص الحماية» أُزيلتا لأنهما لا تُثبتان، وحلّت محلّهما بصمة SHA-256 لكل ملف.

## 8) بصمات الملفات تلقائياً (SHA-256)

أنشئ سرّاً في المستودع: **Settings ← Secrets and variables ← Actions ← New repository secret** باسم `APP_SOURCES` وقيمته نفس JSON الخاص بـ `SOURCES`. ثم تبويب **Actions ← «تحديث بصمات التطبيقات» ← Run workflow**. يحمّل السكربت كل APK ويكتب في `apps.json` الحجم والتاريخ والبصمة ويحفظها في المستودع، ويعيد ذلك كل 6 ساعات دون تعديل إن لم يتغيّر شيء. أو محلياً: `APP_SOURCES='{...}' node tools/refresh-apps.mjs apps.json`.
بعد نشر إصدار جديد قد تختلف البصمة المعروضة عن الملف حتى يعمل السكربت، فشغّله يدوياً بعد كل إصدار.

## 9) تقرير الإدارة

إن أضفت `ADMIN_KEY`: `curl -H "Authorization: Bearer <ADMIN_KEY>" https://<worker>/api/admin/report` يعرض التحميلات لكل تطبيق وعدد الأجهزة وتحميلات آخر 30 يوماً. وللتصحيح الذاتي للأرقام: `curl -X POST -H "Authorization: Bearer <ADMIN_KEY>" https://<worker>/api/admin/reconcile`.

## 10) متغيرات متقدمة للـ Worker

- `DOWNLOAD_MODE=redirect`: يحوّل الزائر إلى رابط المصدر ويحتسب عند **بدء** التحميل (أخف لكن أقل دقة ويكشف الرابط). الافتراضي `proxy`.
- `ALLOWED_ORIGINS`: نطاقات إضافية مسموحة (نطاق مخصّص، أو `http://localhost:8000` للتجربة).
- `UPSTREAM_HOSTS`: مضيفو الملفات المسموحون مفصولون بفواصل (الافتراضي `github.com`).

## 11) اختبارات أُجريت على هذه النسخة

- خادم العدّاد في بيئة workerd الحقيقية مع D1: 48 فحصاً (تكرار، إلغاء منتصف التحميل، استعادة الجهاز، التلاعب بالتذاكر، حدود المعدّل، أولوية `SOURCES` السرّي، توحيد المعرّفات، غياب أي نقطة حذف).
- متصفح حقيقي (Chromium يحاكي هواتف أندرويد) مع الخادم: 43 فحصاً (نقرات متكررة، اكتمال، مسح البيانات، جهاز آخر، تطبيق ثالث بمعرّف بحرف كبير، وضع الخصوصية الوحيد، غياب أي أثر لـ GitHub، تعطّل الخادم، وحجم صفوف الجوال وأيقوناته).
- فحص إمكانية الوصول (axe-core، WCAG AA) بلا مخالفات في المظهرين الداكن والفاتح ولكل النوافذ.
- لم يُجرَّب على Cloudflare الفعلي ولا على هواتف حقيقية؛ اختبر بعد النشر: حمّل من هاتفك وراقب `/api/stats`.
